# Выведено из эксплуатации

Здесь лежит код, который больше не выполняется, но который жалко и незачем
удалять. Он не импортируется ниоткуда из живого дерева — проверять это надо
именно так, поиском по `src/`, а не на глаз.

Отдельная папка, а не удаление, по одной причине: всё это работало и стоило
времени. Удалённое из git достаётся только тем, кто знает, что оно когда-то
было, — а через год не знает никто.

## museum/ + VitrinePage.tsx — трёхмерное здание музея

**Что это.** Бруталистское здание, собранное параметрическим кодом на
three/fiber: ни одного `.glb`, ни одной внешней модели. Перевёрнутый зиккурат
из двух объёмов крест-накрест, консоль на шесть метров над водой, опущенный
двор, восемь залов со своими адресами `/museum/<id>` и уровнями доступа.
Следы опалубки, кессоны и ступени — инстансы, поэтому их сотни, а вызовов
отрисовки единицы. Около 2800 строк.

**Почему не работает.** В `App.tsx`, самой первой строкой компонента:

```js
if (/^\/(?:museum|vitrine|futuroshock)(?:\/|$)/.test(window.location.pathname)) {
  window.location.replace('https://museum.eprisjournal.com/');
  return null;
}
```

Музей переехал на отдельный поддомен — статический сайт с настоящим собранием
(`/opt/museum` на VPS). Все три адреса, которые вели к трёхмерному зданию,
теперь перенаправляются туда, и `return null` срабатывает раньше, чем что-либо
успевает отрисоваться. `VitrinePage` подключался только по `activeTab ===
'museum'`, а этот таб выставляется только из тех же трёх адресов.

Рантайму это ничего не стоило: `lazy()` не загружает чанк, за которым не
пришли. Стоило только чтения — в дереве лежали три с половиной тысячи строк,
про которые не было видно, что они мертвы.

**Как вернуть.** Убрать перенаправление выше, вернуть файлы в `src/`,
восстановить в `App.tsx` ленивый импорт и ветку `activeTab === 'museum'`.
Зависимости (`three`, `@react-three/*`) из проекта никуда не делись — их
использует живой `/stage`, так что ставить заново ничего не придётся.

**Что стоит знать, если вернёте.** Всё нажитое описано в `museum/README.md`
рядом. Коротко, самое дорогое:

- Композиция кадра держится на `radius` в `<CameraRig>`. Объём, вылезший за
  него, просто не попадает в кадр и выглядит «не отрисовался». Проверять
  новые объёмы только глазами, а не по коду.
- `Environment` должно быть ОДНО на оба состояния и переключаться по
  `key={entered}`. Два экземпляра устраивали гонку размонтирования: наружный
  стирал `scene.environment`, и металл в зале рисовался чёрным.
- Западный торец здания так и остался глухой стеной без единого хода. Если
  здание вернётся, там просится солнцерез: западный фасад — единственный, у
  которого солнце низкое и бьёт сбоку, а сцена вращает здание внутри
  неподвижного света, так что торец раз в оборот проходит под скользящим
  лучом и лопасти отработают тенью. Развёртка такого фасада, посчитанная по
  Модулору, уже сделана — на главной museum.eprisjournal.com, в полосе под
  первым экраном (`BAND_JS` в `/opt/museum/build-index.py`); числа и логика
  оттуда переносятся напрямую.
